## 1. 环境要求

| 组件 | 要求 |
|------|------|
| OS | Linux (Ubuntu 22.04 实测) |
| GPU | NVIDIA, 至少 1 张, 建议 24 GB+ |
| Docker | 24+, 安装 [nvidia-container-toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html) |
| 硬盘 | NVMe SSD 推荐, 数据生成对 IO 敏感 |
| 网络 | 能访问 `quay.io` (拉取 Docker 镜像) 和 `github.com` |

确认 nvidia-container-toolkit 已安装：

```bash
docker run --rm --gpus all nvidia/cuda:12.2.0-base-ubuntu22.04 nvidia-smi
```

## 2. 快速迁移步骤

### 2.1 克隆仓库

```bash
git clone https://github.com/hkustgz-linker/FLUX.git
cd FLUX
git checkout dev
```

### 2.2 拉取 Docker 镜像

```bash
docker pull quay.io/zeyinggong/flux:v2_deploy
```

> 也可从已有机器导出再导入：
>
> **导出**（在有镜像的机器上）:
> ```bash
> docker save quay.io/zeyinggong/flux:v2_deploy -o flux_v2_deploy.tar
> rsync -avhP flux_v2_deploy.tar user@new-machine:/path/
> ```
>
> **导入**（在目标机器上）:
> ```bash
> docker load -i flux_v2_deploy.tar
> ```

### 2.3 准备 SAGE-3D 数据

数据生成需要 SAGE-3D 的人物/场景资源。推荐用 rsync 从已有机器同步：

```bash
# 在目标机器上，确保目标目录存在
mkdir -p /mnt/ssd1/zeyingg/SAGE-3D_Official

# 从已有机器同步（替换 USER 和 HOST）
rsync -avhP --progress \
  USER@SOURCE_HOST:/mnt/ssd1/zeyingg/SAGE-3D_Official/ \
  /mnt/ssd1/zeyingg/SAGE-3D_Official/
```

如果无法 rsync 全部 540 GB，至少需要 `v3_tracking_episodes`（约 12 GB）。

SAGE-3D 路径可通过环境变量 `SAGE3D_DIR` 覆盖。

### 2.4 准备 Episode Cache 文件

Cache 文件是场景索引，必须与代码版本匹配。从已有机器同步：

```bash
# 在 FLUX 仓库根目录下
mkdir -p sage_utils/episode_caches

# 从已有机器同步
rsync -avhP --progress \
  USER@SOURCE_HOST:/path/to/FLUX/sage_utils/episode_caches/ \
  ./sage_utils/episode_caches/
```

### 2.5 （可选）准备 Isaac Sim 缓存

缓存可加速 Isaac Sim 首次加载，避免每次重新编译 shader：

```bash
# 从已有机器同步缓存目录
rsync -avhP --progress \
  USER@SOURCE_HOST:~/.cache/flux-isaac-sim/ \
  ~/.cache/flux-isaac-sim/
```

如不传输，首次启动会较慢，但数据生成仍能正常工作。

### 2.6 确认目录结构

```
FLUX/
├── logs_formal_v3/
│   ├── run_distributed.sh       # 分布式调度入口
│   ├── test_mode_gen.sh         # 单 GPU 场景处理脚本
│   └── test_six_combo.sh        # 测试脚本
├── sage_utils/
│   ├── episode_caches/          # 场景→episode 映射缓存（必须）
│   ├── tracking_episode_collection_datagen.py  # 数据生成主程序
│   ├── tracking_episode_collection_camera_only.py  # camera-only 版本
│   ├── patched_base_command.py  # Isaac Sim People 补丁
│   └── generate_episode_tracking_modes.py  # episode 模式生成
├── datagen/
│   └── follow_script/
│       └── cylinder_follow_tracking.py  # follower 行为脚本
└── .gitignore
```

## 3. 文件清单与目录结构

### 数据生成流程

```
run_distributed.sh
  └── 按 GPU round-robin 分配场景
       └── test_mode_gen.sh (每个 GPU 串行执行)
            └── docker run (每个 combo 启动一次容器)
                 └── tracking_episode_collection_camera_only.py
                      └── tracking_episode_collection_datagen.py (main)
```

### 输出目录结构

```
logs_formal_v3/formal_runs/
├── {RUN_NAME}/              # 场景级输出目录（如 0914_84162）
│   ├── stt/                 # 跟踪模式
│   │   └── {ep_id}/
│   │       └── {robot}_{camera}/
│   │           ├── 0.json / 0_info.json
│   │           ├── rgb/
│   │           ├── depth/
│   │           └── frames/
│   ├── dt/
│   ├── at/
│   ├── logs/                # 容器日志
│   └── rejected/            # 被拒绝的 episode
├── launch_logs/             # 运行日志
│   ├── run_{timestamp}.log  # 主日志
│   ├── launch_gpu0.log
│   ├── launch_gpu1.log
│   └── ...
└── 方案说明.md
```

## 4. 运行命令

### 4.1 基本运行（测试）

```bash
cd /path/to/FLUX/logs_formal_v3

SCENE_START=0 SCENE_END=2 GPU_IDS="0" \
  ROBOT_TYPES="go2" CAMERA_TYPES="zed" \
  MAX_EPISODES=1 MAX_STEPS=30 \
  bash run_distributed.sh
```

### 4.2 批量运行（多 GPU, 多场景）

```bash
cd /path/to/FLUX/logs_formal_v3

env SCENE_START=900 SCENE_END=987 GPU_IDS="0 1 2" \
  ROBOT_TYPES="go2 g1 dingo" \
  CAMERA_TYPES="realsense_d435i zed" \
  MAX_EPISODES=10 MAX_STEPS=300 \
  bash run_distributed.sh > formal_runs/m5_scene900_987_v1.log 2>&1
```

### 4.3 环境变量说明

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `SCENE_START` | `0` | 起始场景索引（对应 `episode_caches` 排序后的序号） |
| `SCENE_END` | `2` | 结束场景索引（不包含） |
| `GPU_IDS` | `0 1` | 使用的 GPU ID 列表（空格分隔） |
| `ROBOT_TYPES` | `go2 g1 dingo` | 机器人类型列表 |
| `CAMERA_TYPES` | `realsense_d435i zed` | 相机类型列表 |
| `TRACKING_MODE` | `all` | 跟踪模式：`stt` / `dt` / `at` / `all` |
| `MAX_EPISODES` | `10` | 每种模式最大 episode 数 |
| `MAX_STEPS` | `300` | 每 episode 最大步数 |
| `SAGE3D_DIR` | `/mnt/ssd1/zeyingg/SAGE-3D_Official` | SAGE-3D 数据路径 |
| `SLOT_PER_GPU` | `1` | 每 GPU 同时运行的 slot 数（当前固定为 1） |

### 4.4 日志查看

```bash
# 主日志
tail -f formal_runs/launch_logs/run_{timestamp}.log

# GPU 运行日志
tail -f formal_runs/launch_logs/launch_gpu0.log

# 容器内日志（在场景输出目录下）
cat formal_runs/{run_name}/logs/{mode}/{robot}_{camera}/_container.log
```

### 4.5 中途停止与恢复

按 `Ctrl+C` 会自动清理所有容器。重新运行相同命令会自动跳过已完成的 combo（检测 `_ACCEPTED` 标记）。如果需强制重跑：

```bash
# 删除特定 combo 的完成标记
rm -rf formal_runs/{run_name}/{mode}/{ep_id}/{robot}_{camera}/_ACCEPTED
```

## 5. 故障排查

### 常见问题

| 现象 | 原因 | 解决 |
|------|------|------|
| `ERROR: SCENE_START=900 out of [0, 273)` | episode_caches 缺少文件 | 从已有机器 rsync `sage_utils/episode_caches/` |
| `NameError: name 'frames_dir' is not defined` | 代码版本过旧 | 确认是最新 `dev` 分支代码 |
| `docker: Error response from daemon: ... nvidia` | nvidia-container-toolkit 未装 | 安装并重启 Docker |
| 容器启动非常慢 | Isaac Sim 缓存缺失 | 传输 `~/.cache/flux-isaac-sim/` |
| 数据写入权限错误 | 容器内用户与主机 UID 不匹配 | 运行 `chown -R $(id -u):$(id -g) formal_runs/` |
| `docker: ... too many open files` | 系统 inotify 限制 | `sudo sysctl fs.inotify.max_user_watches=65536` |

## 6. 附录：Docker 镜像维护

当前镜像 `quay.io/zeyinggong/flux:v2_deploy` 基于 Isaac Sim 构建。

如需重新构建：

```bash
# 构建基础镜像（在 FLUX 根目录）
docker build -f docker/Dockerfile.base -t quay.io/zeyinggong/flux:v2_deploy .

# 推送
docker push quay.io/zeyinggong/flux:v2_deploy
```

---

> **注意**：`run_distributed.sh` 默认每 GPU 只运行 1 个串行进程（1 个 Isaac Sim 实例）。这是有意设计的——Isaac Sim 本身是 GPU 密集型应用，多实例并发不会提升吞吐。
